# フェーズ実装の委譲手順

引数で指定されたフェーズ(`docs/DEVELOPMENT_PLAN.md` の Phase N)をサブエージェントに実装させる。

## 手順

1. `docs/DEVELOPMENT_PLAN.md` の該当フェーズを読み、担当モデルを確認する。
   - 担当が「メインセッション」のフェーズはこのスキルの対象外。直接実装する。
2. Agent ツールでサブエージェントを起動する。
   - `subagent_type`: `general-purpose`
   - `model`: 計画書のフェーズ表どおり(`sonnet` または `opus`)
   - フェーズは直列実行。複数フェーズを同時に index.html へ触らせない。
3. プロンプトには必ず以下を含める:
   - 「まず `docs/game-spec.md`、`docs/SPEC_v0.2.md` の該当セクションと `docs/DEVELOPMENT_PLAN.md` の Phase N を読むこと。ランキング関連なら `docs/ranking-spec.md`、タッチ関連なら `docs/mobile-touch-checklist.md` も読むこと」
   - 対象セクション番号の列挙(計画書のフェーズ説明に記載)
   - 絶対制約: index.html 1ファイル完結 / 外部素材・外部JS・外部CSS禁止 / 永続強化禁止 / 既存コードの構造(セクション [A]〜[J])を壊さない
   - 受け入れ基準(計画書から転記)
   - 「コミット・プッシュはしないこと。実装と動作確認のみ行い、変更点の要約を報告すること」
4. サブエージェント完了後、メインセッションが行うこと:
   - `git diff` で差分レビュー(仕様数値、上限処理、削除漏れ、タッチ抑止を重点確認)
   - 問題があれば SendMessage で同じサブエージェントに修正を指示(新規起動せず文脈を維持する)
   - 合格したら `/spec-audit` の該当項目を確認のうえ、メインセッションがコミットする
     - コミットメッセージ: `Phase N: <内容>`
   - `git push -u origin claude/optimistic-cori-5e5735`

## 注意

- ranking_score 合成・復元、二重送信防止、当たり判定チューニングは高難度につきメインセッション直轄(委譲しない)。
- サブエージェントの報告は鵜呑みにせず、必ず差分を自分で確認する。
