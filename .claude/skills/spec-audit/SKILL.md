# 仕様監査手順

`index.html` を `docs/SPEC_v0.2.md` に照らして監査し、項目ごとに ✅/❌/⚠️(要実機確認)で報告する。

## 監査方法

- コードを読んで静的に確認する。Grep で該当処理(touch-action、submit_score、上限値など)を特定してから周辺を読む。
- ranking_score 変換・強化抽選・スコア計算など純粋ロジックは、該当関数を抜き出して `node -e` で実行検証する。
- 実機/ブラウザでしか確認できない項目(ズーム抑止の実挙動、指追従の操作感)は ⚠️ とし、ユーザー実機確認リストに載せる。

## 必須チェック項目

### A. 10大要件(仕様 §39)— 1つでも ❌ なら仕様違反

1. iPhone SE(375px幅)で成立するレイアウト
2. index.html 1ファイル完結(外部JS/CSS/画像/音声なし。Supabase もCDNライブラリではなく fetch 直叩きか確認)
3. 永続強化なし(localStorage に保存してよいのは名前と自己ベストのみ)
4. 戦利品回収→経験値→レベルアップの動線がある
5. 強化は7種(弾数+1×3 / 連射×4 / 貫通×1 / シールド×3 / 耐久×3 / 回収範囲×3 / 判定縮小×2)、上限到達分は抽選除外、全上限でスコアボーナス
6. 30ウェーブ制、5/10/15/20/25/30 波にボス
7. ranking_score = progress×10,000,000 + 表示スコア(クリアは progress=31)、表示時に復元
8. 結果画面下部にランキング上位10件(同率順位 1位/1位/3位)
9. CSS(touch-action/user-select/touch-callout/overflow)と JS(touchmove preventDefault)の両方でタッチ抑止。ホーム・結果画面はスクロール可
10. submit_score 自動送信 / リタイア時非送信 / 二重送信防止 / 失敗時表示

### B. 数値仕様の照合

- 初期値: 耐久3、シールド0、弾数1、Lv.1(§14)
- スコア表: 小100 / 中300 / 大800 / ボス5,000 / 戦利品30 / 突破=波×500 / クリア20,000(§23)
- レベル上限 Lv.12、以降はスコア加算(§20)
- 名前: 必須・最大10文字・localStorage・絵文字可(§8)
- カウントダウン 3→2→1→GO、進行中はゲーム停止(§9)
- 被弾: シールド優先消費→耐久、無敵時間あり(§14)

### C. 不具合一覧(§36)の静的確認

特に: 画面外オブジェクトの削除漏れ、強化上限後の再抽選、内部スコアの画面表示、二重送信。

### D. 報告形式

```
## 監査結果(対象: <範囲>)
✅ 合格: N件 / ❌ 不合格: N件 / ⚠️ 実機確認待ち: N件

### ❌ 不合格(差し戻し対象)
- <項目>: <該当箇所 file:line> <理由>

### ⚠️ 実機確認リスト
- <項目>
```

❌ がある場合は、担当フェーズのモデルへの差し戻し指示文も併記する。
