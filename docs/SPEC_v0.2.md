# マロン飛行 開発要件仕様書 v0.2

## 0. この仕様書の目的

この文書は、ブラウザゲーム 「マロン飛行」 を開発するための要件仕様書です。

第三者、Claude、ChatGPTなどがこの文書だけを読んでも、ゲーム内容、画面構成、ランキング仕様、スマホ対応、タップ処理の注意点、Supabase連携まで分かる状態にすることを目的とします。

このゲームは、スマホで遊べる2D縦スクロール飛行機シューティングです。
ただ敵を撃つだけではなく、敵が落とした戦利品を拾い、1プレイ中だけ機体を強化しながら30ウェーブ突破を目指します。

既存の商用ゲームをそのままコピーしないでください。
参考にするのは「縦スクロール」「敵を倒す」「戦利品で強化する」「ウェーブ制」「スコアを競う」という遊びの構造だけです。機体、敵、演出、画面構成、文言、ゲーム名はオリジナルにしてください。

## 2. 開発の大前提

このプロジェクトでは、パソコン前提のゲームではなく、スマホで直接遊べるブラウザゲームを作ります。

特に iPhone SE級の小さい画面でも遊べること を必須条件にします。
表示が大きな端末で綺麗でも、iPhone SEでボタンが押せない、情報が画面外に出る、指で機体が見えない、画面が横にずれる、スクロールが暴発する場合は不具合として扱います。

確認対象の優先順位は以下です。

| 優先度 | 端末 |
|---|---|
| 最重要 | iPhone SE級の小さい縦画面 |
| 重要 | iPhone 17 Pro |
| 重要 | iPhone 11 Pro |
| 補助 | iPad Pro 2018 |

画面は縦向きを基本にします。
横画面でも完全に壊れないことが望ましいですが、主対象はスマホ縦画面です。

## 3. ファイル構成

初回版は、必ず1ファイルで作ります。

```
index.html
```

index.html の中に、HTML、CSS、JavaScriptをすべて含めます。

外部ファイル分割はしません。
画像素材、音声素材、別JavaScriptファイル、別CSSファイルは初回版では使いません。

理由は、Codeberg Pagesでの公開と差し替えを簡単にし、iPhoneだけでも管理しやすくするためです。

---

## 4. ゲームの中心コンセプト

マロン飛行の中心は、次の流れです。

敵を倒す
↓
戦利品が落ちる
↓
危険を承知で拾いに行く
↓
経験値が増える
↓
機体がレベルアップする
↓
ランダム強化で強くなる
↓
さらに先のウェーブへ進む

単なる弾避けゲームではありません。
戦利品を拾って機体を育てること をゲームの醍醐味にします。

安全に避けるだけでは後半が苦しくなります。
しかし、戦利品を拾いに行くと敵弾に当たりやすくなります。

この「拾いたいけど危ない」という判断を、ゲームの面白さとして作ります。

---

## 5. 永続強化について

永続強化は入れません。

プレイヤーは毎回、同じ初期状態から始めます。
ゲーム中に得たレベル、強化、経験値、シールドなどは、そのプレイ中だけ有効です。

ブラウザを閉じても、次回の機体が強くなっていることはありません。

理由は、ランキングの公平性を保つためです。
全員が毎回同じ初期条件から始めることで、到達ウェーブとスコアを比べやすくします。

## 10. ゲーム画面仕様

ゲーム画面は、スマホ縦画面で見やすく作ります。

### 画面上部

画面上部には、プレイ中に必要な情報を固定表示します。

| 位置 | 表示 |
|---|---|
| 左上 | 現在ウェーブ |
| 中央上 | スコア |
| 右上 | リタイアボタン |
| 上部の補助表示 | Lv、経験値、耐久、シールド |

一時停止を入れる場合は、リタイアとは別にしてください。
ただし、初回版では一時停止なしでも構いません。リタイアは必須です。

### 画面中央

画面中央はプレイ領域です。

表示するものは以下です。

| 種類 | 内容 |
|---|---|
| プレイヤー機体 | 画面下側に表示 |
| 敵 | 上から出現 |
| プレイヤー弾 | 自動で上方向へ発射 |
| 敵弾 | 敵から下方向または斜めに発射 |
| 戦利品 | 敵撃破時に落下 |
| ウェーブ表示 | ウェーブ開始時に短く表示 |
| レベルアップ表示 | 強化内容を短く表示 |

### 画面下部

画面下部は、指で操作する領域です。

プレイヤー機体は、指の真下ではなく、少し上に追従させます。
指で機体が隠れないようにするためです。

## 12. タップ・スマホ操作の注意事項

このゲームはスマホ操作が中心です。
そのため、ブラウザ標準の操作がゲームを邪魔しないようにしてください。

### 必須で抑える操作

| 項目 | 仕様 |
|---|---|
| 横スクロール | 禁止 |
| ピンチズーム | 禁止 |
| ダブルタップ拡大 | 禁止 |
| 長押し選択 | 禁止 |
| 長押しコピー | 原則禁止 |
| 画像保存メニュー | 原則出さない |
| ゲーム中のページスクロール | 禁止 |
| 2本指ジェスチャー | ゲーム中は抑止 |
| タッチ中の選択範囲表示 | 出さない |

### 例外

リンクや外部ページへ移動するボタンは、通常のタップで開けるようにしてください。
ただし、ゲーム中のプレイ領域では長押しメニューやスクロールが出ないようにします。

### 実装上の注意

CSSとJavaScriptの両方で対策してください。

CSSでは、以下のような考え方を使います。

```css
html, body {
  margin: 0;
  overflow: hidden;
  overflow-x: hidden;
  touch-action: none;
  user-select: none;
  -webkit-user-select: none;
  -webkit-touch-callout: none;
}
```

ただし、ホーム画面や結果画面で通常スクロールが必要な場合は、画面ごとに制御してください。
ゲーム中だけ完全にスクロールを止める形が望ましいです。

JavaScript側でも、ゲーム中の touchmove でページスクロールが発生しないようにしてください。

## 13. iPhone SE対応

iPhone SE級の小さい画面を基準に、以下を守ってください。

| 項目 | 仕様 |
|---|---|
| 文字 | 小さすぎない |
| ボタン | 指で押せる高さを確保 |
| 画面幅 | 横にはみ出さない |
| ランキング | 横スクロールなしで読める |
| ゲーム情報 | 上部に詰め込みすぎない |
| プレイ領域 | 敵弾を避けられる高さを確保 |
| 結果画面 | 下部ランキングまで自然に読める |

小さい画面で、スコア、ウェーブ、Lv、耐久、シールドを全部大きく出すと、プレイ領域が狭くなります。
そのため、上部表示はコンパクトにまとめてください。

## 14. プレイヤー機体仕様

初期状態は以下です。

| 項目 | 初期値 |
|---|---|
| レベル | Lv.1 |
| 最大耐久 | 3 |
| 現在耐久 | 3 |
| シールド | 0 |
| 弾数 | 1 |
| 連射速度 | 標準 |
| 貫通弾 | なし |
| 回収範囲 | 標準 |
| 当たり判定 | 標準 |

被弾時は、まずシールドを消費します。
シールドがない場合は耐久が1減ります。

耐久が0になるとゲームオーバーです。

被弾後は、短時間だけ無敵時間を入れてください。
連続被弾で一瞬でゲームオーバーになるのを防ぐためです。

---

## 15. 自動ショット仕様

プレイヤー機体は、自動で弾を撃ちます。

| 項目 | 仕様 |
|---|---|
| 発射方向 | 上方向 |
| 発射方式 | 一定間隔で自動発射 |
| 初期弾数 | 1 |
| 弾数強化 | 最大で追加3回 |
| 連射強化 | 最大で4回 |
| 貫通弾 | 1回取得で有効 |

弾数が増えた場合は、横に広がる形で発射します。
連射速度が上がった場合は、弾の発射間隔を短くします。

貫通弾を取得した場合、プレイヤー弾は敵に当たってもすぐ消えず、一定回数または一定距離まで貫通します。

---

## 16. 敵仕様

敵は画面上から出現します。

初回版では、敵の種類は増やしすぎず、役割が分かるようにします。

| 敵タイプ | 内容 |
|---|---|
| 小型敵 | 体力が低い。基本の敵 |
| 中型敵 | 少し硬い。弾を撃つ |
| 大型敵 | 硬い。戦利品を落としやすい |
| ボス | 5波ごとに出現 |

敵はウェーブが進むほど強くなります。

強くする要素は以下です。

| 要素 | 内容 |
|---|---|
| 体力 | 後半ほど増える |
| 出現数 | 後半ほど増える |
| 移動 | 横移動や蛇行を追加 |
| 敵弾 | 後半ほど増える |
| 戦利品 | 強い敵ほど落としやすい |

---

## 17. 戦利品仕様

敵を倒すと、一定確率で戦利品を落とします。

戦利品は、プレイヤーが近づくと回収されます。
回収範囲アップの強化を取ると、より遠くの戦利品も拾えるようになります。

### 戦利品の見た目

| 表示 | 内容 |
|---|---|
| 🔧 | 通常戦利品 |
| ✨ | 大きい戦利品 |
| 🎁 | ボス戦利品 |

### 戦利品の効果

| 種類 | 効果 |
|---|---|
| 通常戦利品 | 経験値を少し増やす |
| 大きい戦利品 | 経験値を多めに増やす |
| ボス戦利品 | 経験値を大きく増やす |

戦利品を拾った時に、スコアも少し増やします。

---

## 18. レベルアップ仕様

敵が落とした戦利品を拾うと、経験値が増えます。
経験値が一定量に達すると、機体レベルが上がります。

レベルアップ時は、以下の強化候補から1つをランダムで付与します。

プレイヤーは強化を選びません。
ランダムで成長することで、毎回違うプレイ感を作ります。

---

## 19. 強化候補

### 攻撃型

| 強化 | 内容 | 上限 |
|---|---|---|
| 弾数+1 | 同時に撃つ弾が増える | 3回 |
| 連射速度アップ | 弾を撃つ間隔が短くなる | 4回 |
| 貫通弾 | 弾が敵を貫通する | 1回 |

### 防御型

| 強化 | 内容 | 上限 |
|---|---|---|
| シールド+1 | 被弾を1回防ぐ | 3回 |
| 最大耐久+1 | 最大耐久が増え、現在耐久も1回復する | 3回 |

### 回避型

| 強化 | 内容 | 上限 |
|---|---|---|
| 回収範囲アップ | 戦利品を拾える距離が広がる | 3回 |
| 当たり判定縮小 | 敵弾に当たる範囲が小さくなる | 2回 |

すでに上限に達した強化は抽選対象から外します。
全強化が上限に達している場合は、レベルアップ時にスコアボーナスを付与します。

---

## 20. レベル上限

初回版のレベル上限は Lv.12 とします。

Lv.12到達後も戦利品は拾えます。
ただし、経験値ではなくスコア加算に変えます。

---

## 21. ウェーブ仕様

ゲームは30ウェーブ制です。

| 区間 | 内容 |
|---|---|
| 1〜5波 | 基本操作、戦利品回収に慣れる |
| 6〜10波 | 横移動する敵、弾を撃つ敵を追加 |
| 11〜15波 | 中型敵、大型敵を増やす |
| 16〜20波 | 敵弾と編隊を増やす |
| 21〜25波 | 強化不足だと突破が難しくなる |
| 26〜29波 | 高密度の最終区間 |
| 30波 | 最終ボス |

5、10、15、20、25、30波にはボスを出します。

30波のボスを倒すとゲームクリアです。

---

## 22. 到達ウェーブの考え方

ランキングでは、単なるスコアではなく、どこまで進んだかを重視します。

到達ウェーブは、プレイヤーが実際に到達した一番大きいウェーブです。

例です。

| 状態 | 表示 |
|---|---|
| 1波でゲームオーバー | 1波到達 |
| 17波でゲームオーバー | 17波到達 |
| 30波ボスで敗北 | 30波到達 |
| 30波ボス撃破 | 30波クリア |

30波到達と30波クリアは別扱いです。
30波クリアの方が上になります。

---

## 23. スコア仕様

スコアは、敵撃破、戦利品回収、ウェーブ突破、クリアで増えます。

| 行動 | 点数 |
|---|---|
| 小型敵撃破 | 100点 |
| 中型敵撃破 | 300点 |
| 大型敵撃破 | 800点 |
| ボス撃破 | 5,000点 |
| 戦利品回収 | 30点 |
| ウェーブ突破 | ウェーブ数 × 500点 |
| 30波クリア | 20,000点 |

スコアは、同じ到達ウェーブの人同士の順位を決めるために使います。

## 24. ランキング仕様

ランキングは、Supabaseに送信します。
このゲームではSupabase連携を必須とします。

ランキングは、以下の順で評価します。

1. 30波クリアしているか
2. 到達ウェーブが高いか
3. 同じ到達ウェーブならスコアが高いか

### 表示例

17波到達　184,500点

クリア時は以下です。

30波クリア　312,000点

### 内部ランキングスコア

既存のランキング処理では、基本的に1つの数値で順位を並べます。
そのため、Supabaseへ送るスコアは、到達ウェーブと通常スコアを合成した数値にします。

```
ranking_score = 進行度 × 10,000,000 + 表示用スコア
```

進行度は以下です。

| 状態 | 進行度 |
|---|---|
| 1波到達 | 1 |
| 10波到達 | 10 |
| 30波到達、未クリア | 30 |
| 30波クリア | 31 |

例です。

17波到達 184,500点
→ 17 × 10,000,000 + 184,500
→ 170,184,500

この 170,184,500 は内部用です。
画面には表示しません。

画面には必ず、以下のような人間が読める形で表示してください。

17波到達　184,500点

## 27. ランキング送信タイミング

ランキング送信は、結果画面に入った時点で自動実行します。

| 状態 | 送信 |
|---|---|
| 耐久0でゲームオーバー | 送信する |
| 30波クリア | 送信する |
| リタイア | 送信しない |
| 通信失敗 | 失敗表示。ゲームは続行可能 |

ゲーム終了時に自動送信し、プレイヤーに「登録する」ボタンを押させないでください。

ただし、二重送信は防いでください。
結果画面を何度も開いたり、ボタンを連打したりしても、同じプレイ結果が複数回送信されないようにします。

## 31. Supabase送信内容

既存の共通RPC submit_score を使う場合、最低限以下を送ります。

| 項目 | 内容 |
|---|---|
| p_display_name | プレイヤー名 |
| p_game_slug | maron_hikou |
| p_score | ranking_score |
| p_client_version | バージョン文字列 |

ただし、画面表示では p_score をそのまま出さないでください。
p_score は到達ウェーブ優先にするための内部スコアだからです。

ランキング表示時には、内部スコアから到達状態と表示用スコアを復元する必要があります。

復元方法は以下です。

```
progress = Math.floor(ranking_score / 10,000,000)
display_score = ranking_score % 10,000,000
```

progress が 31 なら 30波クリア と表示します。
progress が 30 以下なら progress波到達 と表示します。

## 32. 実験場への追加注意

現状の実験場トップと詳細ランキングページは、Supabaseの games テーブルだけで完全自動生成される前提ではありません。

そのため、新規ゲームを実験場に出す場合は、以下を両方確認してください。

1. Supabaseの games テーブルへ maron_hikou を登録する
2. 実験場トップ側のゲーム一覧にも maron_hikou を追加する
3. 詳細ランキングページ側のゲーム一覧にも maron_hikou を追加する

Supabaseに登録しただけで実験場に表示されるとは限りません。
ここは作業漏れしやすいので注意してください。

## 33. 初回版で入れないもの

初回版では、以下は入れません。

| 入れないもの | 理由 |
|---|---|
| 永続強化 | ランキングの公平性を保つため |
| 機体選択 | 調整量が増えすぎるため |
| 武器ショップ | 1プレイ内強化に集中するため |
| 必殺技 | 操作を増やしすぎないため |
| ステージ選択 | 30ウェーブ挑戦に集中するため |
| オンライン対戦 | 今回の目的と違うため |
| BGM・効果音 | 初回は動作安定を優先するため |
| 外部画像 | 1ファイルで扱いやすくするため |

## 34. デザイン方針

マロン飛行は、スマホで見やすい軽いデザインにします。

### 推奨する雰囲気

| 項目 | 方針 |
|---|---|
| 背景 | 空、雲、夕焼けなどをCSSで表現 |
| プレイヤー | 絵文字またはCSS図形で表現 |
| 敵 | 小型機・中型機・大型機が分かる見た目 |
| 戦利品 | 🔧、✨、🎁などで分かりやすく |
| 色 | 見やすさ優先 |
| エフェクト | 軽くする |

見た目を豪華にしすぎて、動作が重くならないようにしてください。
特にiPhone SE級の画面で、弾や敵が増えても遊べることを優先します。

## 35. パフォーマンス要件

スマホブラウザで動くため、処理を軽くしてください。

| 項目 | 仕様 |
|---|---|
| 描画 | Canvas推奨 |
| 画面更新 | requestAnimationFrame |
| オブジェクト管理 | 敵、弾、戦利品を配列で管理 |
| 削除処理 | 画面外、撃破済み、回収済みは必ず削除 |
| 最大表示数 | 敵弾や戦利品を増やしすぎない |
| ランキング取得 | 結果画面で必要分だけ取得 |

敵、弾、戦利品が画面外に出たあとも配列に残り続けると、後半で重くなります。
必ず削除してください。

## 36. 不具合として扱うもの

以下は不具合として修正対象にします。

| 不具合 | 内容 |
|---|---|
| iPhone SEで画面がはみ出す | 横スクロールが出る |
| ゲーム中にページが動く | スワイプで画面全体がスクロールする |
| ダブルタップで拡大する | 操作中に画面がズームする |
| 長押しメニューが出る | ゲームプレイが止まる |
| 指で機体が見えない | 操作性が悪い |
| 弾が当たっていないのに被弾する | 当たり判定が大きすぎる |
| 戦利品を拾ったのに反映されない | 経験値、スコア、回収数が増えない |
| レベルアップしない | 経験値上限処理の不具合 |
| 強化上限後に同じ強化が当たる | 再抽選できていない |
| 30波まで進めない | ウェーブ進行の停止 |
| 結果が二重送信される | ランキング登録の不具合 |
| ランキングに内部スコアが出る | 表示変換の不具合 |
| 結果画面下部にランキングが出ない | 必須表示漏れ |

## 39. 重要な実装方針まとめ

マロン飛行で必ず守ることは以下です。

1. iPhone SE級の小さい画面でも遊べること
2. HTML、CSS、JavaScriptを1つの index.html にまとめること
3. 永続強化を入れないこと
4. 戦利品回収とレベルアップをゲームの中心にすること
5. 強化は指定された7種類からランダム付与にすること
6. 30ウェーブ制にすること
7. ランキングは到達ウェーブ優先にすること
8. 結果画面下部にランキングを掲載すること
9. ゲーム中のズーム、長押し、スクロール、誤タップを抑えること
10. Supabaseへランキング連携すること

この10点から外れた場合は、仕様違反として扱います。
