# 04. テスト・リリース・再監査チェックリスト

## 1. 実行方法

このプロジェクトは外部依存なしの静的HTMLである。ブラウザのローカルファイル制約や共有API確認のため、**任意の静的HTTPサーバー**経由でリポジトリ直下の`index.html`を配信して確認する。開発環境で定められた静的サーバー起動手順を優先し、確認URLは通常 `http://localhost:<port>/` となる。変更前後の比較では、ブラウザキャッシュを無効化するか、クエリ文字列付きで開く。

> 注意: 本番ランキングの実RPCを検証する際は、テスト用のゲームslugまたはテスト環境を使う。監査・開発目的で本番ランキングへ偽の結果を送信してはならない。

## 2. 自動・半自動で確認する項目

| 区分 | 検証 | 合格条件 | 失敗時の切り分け |
|---|---|---|---|
| 構文 | HTML内スクリプトを抽出して構文検査、またはブラウザコンソール確認。 | JavaScriptエラーなし。 | 直前の編集箇所、括弧、テンプレート文字列、DOM IDを確認。 |
| 再現性 | 同seedで敵出現、ドロップ、強化列を2回比較。 | 完全に一致。 | `Math.random()`の残存箇所、演出乱数との混在を検索。 |
| 強化下振れ | 100,000試行の成長監査。 | W5直前の攻撃強化ゼロ率0%。 | 初回保証条件、候補上限フィルタ、レベル到達条件を確認。 |
| TTK | W5/W10/W20/W30の理論TTK分布を出力。 | W30 P10〜P90幅20秒以下を目安。 | 基礎DPS、弾数、連射、ボスHP、敵密度の変更点を分離。 |
| 追従 | 30/60/120fps相当の`delta`列で90%到達時間を計測。 | 各条件で基準±10%。 | `delta`未使用の補間、`delta`上限、クランプを確認。 |
| 波進行 | 敵全滅、敵逃走、ボス撃破、リタイアで状態遷移を確認。 | 1〜30波が停止せず進む。W30のみクリア。 | `waveState.queue`、`enemies`の削除、次波タイマーを確認。 |
| スコア | 合成・復元、クランプ、同率順位を確認。 | 内部値が表示されず、31=30波クリア。 | `buildRankingScore`、`parseRankingScore`、RPC戻り値を確認。 |

## 3. 成長監査の再実行

申し送りフォルダにあるスクリプトは、現行の敵数、ドロップ率、経験値、強化上限を再現している。ゲームバランスを変更した場合、必ずスクリプト側の定数・ロジックも同じ変更へ追従させる。

```bash
cd maron_hikou
node docs/chatgpt_handover/scripts/audit-growth-distribution.mjs \
  > docs/chatgpt_handover/data/audit-growth-distribution.json
```

次の値をPR本文に記載する。

| 指標 | 現行監査基準 | 改修後に記録する値 |
|---|---:|---|
| W5前・攻撃強化ゼロ率 | 49.141% | 改修後の値 |
| W5 TTK P10/P50/P90 | 12.0 / 24.0 / 24.0秒 | 改修後の値 |
| W30 TTK P10/P50/P90 | 24.6 / 38.5 / 71.0秒 | 改修後の値 |
| W30 TTK幅 | 46.4秒 | 改修後のP90-P10 |
| W30直前のLv P10/P50/P90 | 12 / 12 / 12 | 改修後の値 |

**重要**: 監査スクリプトの「全敵撃破・全戦利品回収・全弾命中」は楽観条件である。数値が合格でも、実プレイが合格したことにはならない。

## 4. ブラウザ機能チェック

### 開始・終了フロー

| 確認 | 手順 | 合格条件 |
|---|---|---|
| ホーム | 初回表示を確認。 | タイトル、短い説明、開始、ルール、共有、実験場導線がある。 |
| 名前入力 | 空欄で開始を試す。日本語・絵文字・10文字を入力。 | 空欄は開始不可。文字が壊れず、次回も保存名が表示される。 |
| カウントダウン | 開始直後を観察。 | 3→2→1→GO。敵・弾・スコアはGO前に進まない。 |
| リタイア | ゲーム中に押し、キャンセルと確定を試す。 | 確認モーダル中はゲームが停止。確定時は送信しない。 |
| ゲームオーバー | 耐久0まで被弾。 | 結果画面へ1回だけ進み、送信状態を正しく表示。 |
| クリア | W30ボス撃破。 | 30波クリア、進行度31、クリアボーナス、送信が1回だけ。 |
| リトライ | 結果から複数回再開。 | 前プレイの敵、弾、戦利品、HUD、送信フラグが残らない。 |

### 入力・画面

| 確認 | 合格条件 |
|---|---|
| Pointer移動 | 指を動かした位置の約70論理px上へ機体が追従し、画面端で正常にクランプする。 |
| 指離し | 最終目標位置へ追従したのち、意図せず動き続けない。 |
| ゲーム中スクロール | 1本指ドラッグでページが動かない。 |
| ズーム・長押し | ダブルタップ、ピンチ、長押しでズーム・選択・コンテキストメニューが出ない。 |
| 画面外導線 | ホーム・結果の通常リンクと必要なスクロールは妨げない。 |
| HUD | W、スコア、Lv、経験値、耐久、シールド、リタイアが重ならず読める。 |
| 戦利品 | 近づくと確実に吸引・回収され、経験値・スコア・回収数が更新される。 |

## 5. iPhone SE級の実機確認

実機確認は静的解析で代替できない。優先順は、iPhone SE級、iPhone 17 Pro、iPhone 11 Pro、iPad Pro 2018である。

| テスト場面 | 観察する値 | 合格の目安 |
|---|---|---|
| ホーム / 名前 / 結果 | 横はみ出し、入力キーボード、下部ランキング。 | 横スクロールなし。入力可能。結果ランキングまで到達できる。 |
| W1〜W5 | 指追従、初期HUD、回収円、カウントダウン。 | 反応遅れで被弾しない。HUDがプレイ領域を圧迫しない。 |
| W21〜W25 | 敵・弾・戦利品が多い局面。 | 明確なフレーム落ち、弾の瞬間消失、操作遅延増大がない。 |
| W26〜W30 | tier3ボス円形弾 + 護衛。 | 端末発熱・FPS低下でも追従感が大きく変わらない。 |
| 結果・送信 | 通信遅延・失敗時。 | 送信中/成功/失敗が理解でき、二重送信しない。 |

実機で問題が出た場合、動画・端末名・OS・ブラウザ・発生波・再現手順を必ず記録する。「重い」「難しい」だけでは調整できない。

## 6. Supabase・ランキングの検証

| 項目 | 実行内容 | 合格条件 |
|---|---|---|
| `submit_score` | テストデータで1回だけ送信。 | 成功応答。二重送信なし。 |
| 異常値 | 負値、進行度0/32、表示スコア10,000,000以上、長い表示名。 | RPCが拒否または安全に補正。 |
| リタイア | リタイア後のネットワークを確認。 | `submit_score`を呼ばない。 |
| 取得RPC | `p_limit`あり/なしの両経路を確認。 | 上位10件が表示される。 |
| 復元表示 | 進行度17、30、31を用意。 | `17波到達`、`30波到達`、`30波クリア`と正しく表示。 |
| 同率 | 同じ合成スコアの複数行。 | 1位、1位、3位方式。 |
| 不正対策 | クライアント外から不正値を送るテストをテスト環境で実施。 | サーバーで拒否される。 |

## 7. リリース判定

次の全項目を満たすまで、競技ランキングとしての公開判定を出さない。

- [ ] 強化下振れ保護が統計検査で合格している。
- [ ] 固定seed競技またはランキング対象の公平性方針が実装・文書化されている。
- [ ] 30/60/120fpsで追従時間の差が±10%以内である。
- [ ] W5/W10/W20/W30のTTK分布を再測定し、受け入れ基準を満たす。
- [ ] 逃走敵の設計意図が仕様と結果画面へ反映されている。
- [ ] 弾上限で既発射弾を恣意的に消さない、または発生側で制御している。
- [ ] iPhone SE級と後半W26〜W30の実機確認が完了している。
- [ ] Supabaseの送信・取得・同率・異常値・二重送信をテスト環境で確認している。
- [ ] ランキングRPCがクライアント任意値を無条件採用しない。
- [ ] 仕様書、申し送り、監査生データが改修後の実装値と一致している。
