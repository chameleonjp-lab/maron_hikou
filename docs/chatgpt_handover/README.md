# マロン飛行 — ChatGPT向け申し送り

**作成日**: 2026-08-16

**対象ブランチ**: `docs/chatgpt-handover-maron-hikou-20260816`

**対象成果物**: `index.html` のみで完結する、スマホ向け縦スクロール・シューティング

**このフォルダの目的**: 次の担当者が既存実装を破壊せず、優先順位を誤らず、再現可能な検証を伴って改善できるようにする。

> **最優先の結論**: 現在のゲームは「倒す → 戦利品を拾う → 1プレイ内で育つ」というコア体験が成立している。一方で、競技ランキングとしては、ランダム成長・端末FPS依存の追従・クライアント完結のスコア送信が公平性を損なう。次の改修は演出追加ではなく、**下振れ防止・再現性・端末間公平性**から着手すること。

## 変更してよいもの・変更前に守るもの

| 区分 | 内容 |
|---|---|
| **最初に変更してよい** | 強化抽選の下振れ保護、追従のフレーム独立化、計測・テスト、競技用seedの導入設計。 |
| **設計確認が必要** | ボスHP、敵密度、ドロップ率、スコア式、ランキングRPCの仕様。これらは単独で変えると難易度・順位を壊す。 |
| **触らない** | Supabase URL / Publishable Key、ゲーム識別子 `maron_hikou`、合成スコアの桁構造、公開URL。変更が必要な場合は既存の実験場・Supabase側と同時に確認する。 |
| **追加禁止** | 初回版の範囲外である永続強化、機体選択、武器ショップ、必殺技、外部アセット依存。 |

## 直近の推奨タスク

1. **W5前の攻撃強化ゼロ確率を0%にする。** 初回レベルアップ時の攻撃系保証、または攻撃を含む3択方式を導入する。
2. **追従補間を`delta`依存に修正する。** 現状はフレームごとに35%追従するため、低FPS端末ほど操作が重くなる。
3. **競技モードを固定seed化する。** 敵、ドロップ、強化候補の乱数を再現可能にし、ランキングとランダム通常モードを分ける。
4. **ボスTTKを定量再調整する。** W30の楽観TTK分布をP10〜P90で20秒以内に収める。
5. **ランキングRPCをサーバー側で検証する。** クライアントから送られた`p_score`を無条件にランキング化しない。
