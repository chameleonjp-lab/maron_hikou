# マロン飛行 ゲーム仕様書(共通テンプレート形式)

この文書は `docs/game-spec-template.md`(共通テンプレート)の形式に沿った maron_hikou のゲーム仕様書です。
数値・文言・画面構成の詳細は `docs/SPEC_v0.2.md`(唯一の正)を参照してください。
本書と SPEC_v0.2.md が食い違う場合は SPEC_v0.2.md を優先し、本書を直します。

## 1. 基本情報

- ゲーム名:マロン飛行
- リポジトリ名:maron_hikou
- game_slug:maron_hikou
- 公開URL:https://chameleonjp.codeberg.page/maron_hikou/
- 対象端末:iPhone SE級を含むスマホ縦画面
- 公開先:Codeberg Pages
- 構成:HTML・CSS・JavaScript を `index.html` 1ファイルにまとめる(npm・Node・ビルドツール・外部フレームワーク不使用)

## 2. ゲーム概要

2D縦スクロール飛行機シューティング。
敵を倒し、敵が落とした戦利品を回収して経験値を貯め、1プレイ中だけ機体をレベルアップ・強化しながら30ウェーブ突破を目指す。
永続強化はなし。強化はそのプレイ限りでリセットされる。

## 3. 画面構成

- ホーム画面:あり
- 名前入力またはカウントダウン:両方あり(名前入力 → 3秒カウントダウン)
- ゲーム画面:あり(Canvas + 上部HUD)
- 結果画面:あり(下部にランキング表示)

必須要素:

- ゲームをシェア(Web Share API、不可ならコピー)
- 実験場へ(https://chameleonjp-lab.github.io/chameleonjp_lab/)

## 5. ゲーム画面

表示するもの:

- 現在ウェーブ(左上)
- スコア(中央上)
- リタイアボタン(右上)— 必要。確認ダイアログ付き
- 補助表示:Lv・経験値・耐久・シールド(上部にコンパクトに)
- プレイ領域:機体・敵・自弾・敵弾・戦利品・ウェーブ表示・レベルアップ表示

## 6. 操作

- タップ・なぞり:機体移動(指の少し上に機体を追従させ、指で隠さない)
- スワイプ:機体移動と同じ(ページスクロールは発生させない)
- 長押し:割り当てなし(メニュー抑制)
- 2本指操作:割り当てなし(ゲーム中は抑止)
- 画面外タップ:無効
- 連打時の扱い:ボタンの二重発火防止(特にランキング送信・画面遷移)
- ショット:自動発射(発射ボタンなし)
- 戦利品回収:機体が近づくと自動回収

## 7. スマホ操作対策

- 横スクロール:禁止
- 長押しメニュー:ゲーム中は抑制
- テキスト選択:ゲーム中は抑制
- ダブルタップ拡大:抑制
- ピンチズーム:ゲーム中は禁止
- ゲーム中スクロール:抑制(CSS `touch-action` 等と JS `touchmove` の両方で対策)
- タップ処理の二重発火対策:必須(pointer/touch イベントの重複処理に注意)
- iPhone SEでの注意:上部HUDをコンパクトにしプレイ領域の高さを確保。下部ボタンは `safe-area-inset-bottom` 考慮。結果画面は縦スクロールで下部ランキングまで読める
- 例外:ホーム画面・結果画面は通常スクロール可。リンク・入力欄は通常タップ可能のまま

詳細は `docs/mobile-touch-checklist.md` と SPEC_v0.2.md §12〜13。

## 8. ゲームルール

- 30ウェーブ制。5・10・15・20・25・30波にボス。30波ボス撃破でクリア。
- 敵:小型・中型・大型・ボスの4種。ウェーブが進むほど強化(SPEC §16・§21)。
- 被弾:シールド優先消費 → 耐久-1。被弾後は短い無敵時間。耐久0でゲームオーバー。
- 初期状態:Lv.1、耐久3/3、シールド0、弾数1(SPEC §14)。
- 戦利品:🔧通常 / ✨大 / 🎁ボス。回収で経験値+スコア(SPEC §17)。
- レベルアップ:経験値到達でランダム強化1つ付与。上限 Lv.12(以降の戦利品は経験値の代わりにスコア加算。係数は「戦利品経験値 × 30点」= 通常30点 / 大90点 / ボス240点)。
- 強化候補(7種・上限到達分は抽選除外、全上限時はスコアボーナス):
  - 攻撃型:弾数+1(上限3)/ 連射速度アップ(上限4)/ 貫通弾(上限1)
  - 防御型:シールド+1(上限3)/ 最大耐久+1(上限3)
  - 回避型:回収範囲アップ(上限3)/ 当たり判定縮小(上限2)
- 永続強化:なし(localStorage に保存してよいのは名前と自己ベストのみ)
- リタイア:右上ボタン → 確認 → 結果画面へ(ランキング送信なし)

## 9. スコア仕様

- 内部スコア:整数
- 表示スコア:点数そのまま(例 184,500点)
- 高いほど良い / 低いほど良い:高いほど良い
- 単位:点
- score_scale:1
- score_decimals:0
- 点数表(SPEC §23):小型100 / 中型300 / 大型800 / ボス5,000 / 戦利品30 / ウェーブ突破=波×500 / 30波クリア20,000
- 初回記録の扱い:first_score_label「初回到達」(想定)
- 最高記録の扱い:best_score_label「最高到達」、top_ranking_type は best 想定

### Supabase へ送る合成スコア(重要)

順位は「到達ウェーブ優先、同ウェーブならスコア順」のため、送信値は合成値にする。

```
ranking_score = 進行度 × 10,000,000 + 表示用スコア
進行度 = 到達ウェーブ(1〜30)、30波クリアは 31
表示時の復元: progress = floor(s / 1e7), display_score = s % 1e7
```

- 表示用スコアは 10,000,000 点未満にクランプする(桁あふれ防止)
- **内部合成値は画面に出さない**。必ず「17波到達 184,500点」の形で表示する

## 10. ランキング仕様

- ランキング対応:あり(必須)
- game_slug:maron_hikou
- top_ranking_type:best(想定)
- Supabase送信タイミング:結果画面表示時に自動送信1回(登録ボタンは置かない)
- 送信する値:display_name, game_slug, score(=ranking_score), client_version
- 名前入力:必須(最大10文字、空欄不可、localStorage 保存、絵文字可)
- 二重送信防止:必須(プレイごとの送信済みフラグ。リトライ・画面遷移・連打でも再送しない)
- リタイア時:送信しない(「リタイアのため送信なし」と表示)
- 送信状態表示:送信中 / 送信成功 / 送信失敗(失敗してもゲーム結果は見える)
- 結果画面下部ランキング:あり(上位10件、同率順位は 1位・1位・3位 方式、横スクロールなし)

接続情報・RPC は `docs/ranking-spec.md` の共通仕様に従う。
`submit_score` の引数は `p_display_name` / `p_game_slug` / `p_score` / `p_client_version`(共通テンプレートの実装例で確認済み)。

## 11. 結果画面

- ランキング送信状態(送信中 / 成功 / 失敗 / リタイアのため送信なし)
