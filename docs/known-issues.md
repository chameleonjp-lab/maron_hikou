# よくある問題と確認点

## ランキング登録できない

確認すること：

- Supabase URL
- Publishable key
- `game_slug`
- `submit_score` の引数
- RPCの戻り値
- ネットワークエラー表示

## Supabaseに登録したのに実験場に出ない

実験場側に `GAMES` 配列がある場合、Supabase登録だけでは表示されない。
実験場トップと詳細ランキングページの両方を確認する。

## score_scale不一致

秒や小数表示のゲームでは、内部整数と表示値がずれやすい。
`score_scale` と `score_decimals` を必ず確認する。

## 結果画面にランキングがない

仕様で結果画面下部ランキングが必要な場合、結果画面に表示場所を用意する。
ランキング0件でも表示が壊れないようにする。

## 名前入力が任意のまま

ランキング必須ゲームでは、名前入力を必須にする。
仕様で自動送信と決めたゲームでは、終了時に送信する。

## 二重送信

結果画面表示、リトライ、ホーム移動、連打で複数回送信されないようにする。

## スマホ操作の問題

- 長押しメニュー
- テキスト選択
- ダブルタップ拡大
- ピンチズーム
- ゲーム中スクロール
- 画面下部ボタンが押しにくい

## 古いコードが混ざる

古いコード参照のため、途中版は `index_v2.html`、`index_v3.html` のように名前を変える。
公開正本は常に `index.html`。

## maron_hikou 固有の注意

- 送信スコアは合成値(進行度×10,000,000+表示用スコア)。実験場側でそのまま「点」表示すると桁が壊れて見えるため、表示方法を要確認。
- 表示用スコアが10,000,000点以上になると合成が壊れる。クランプ必須。
- リタイア時の非送信と、耐久0・クリア時の自動送信を取り違えない。

## maron_hikou 実機確認リスト(公開前)

静的監査・node検証では確認不能の項目。iPhone 実機(優先: SE級)で確認する。

- ゲーム中のピンチ/ダブルタップ/長押し/スクロールが実際に抑止されるか(iOS Safari)
- ホーム・結果画面の縦スクロールとモーダル内スクロールが阻害されないか
- 名前入力欄のフォーカス・日本語/絵文字入力・カーソル操作
- 指追従の操作感(70px上オフセット・lerp係数0.35)と機体の視認性
- HUD(耐久6・シールド3表示時)が375px幅で収まるか
- 後半ウェーブ(26〜30波)・tier3ボス円形弾のフレームレート
- get_best_score_ranking RPC の実引数(p_limit対応有無。フォールバック実装済みだが実応答で要確認)
- 同率順位の rank_no がRPCから返るか(返らない場合はクライアント計算で表示)
- 実際の難易度体感(序盤の易しさ、21波以降の歯ごたえ、30波クリア可能性)
